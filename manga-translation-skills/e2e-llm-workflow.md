# 先進漫畫翻譯：端到端 LLM (End-to-End LLM) 工作流程設計

本文件定義一套基於多模態 LLM 的漫畫翻譯工作流程，利用 LLM 一次性輸出原文、譯文、相對邊界框座標與排版設定。

---

## 1. 核心工作流程 (Workflow Pipeline)

整個翻譯框架被壓縮為三個核心步驟：

### Step 1: 圖片準備與輸入 (Image Preparation)
前端或伺服器獲取漫畫原始圖片。為了解決 LLM 不知道原圖絕對像素大小的問題，我們在設計 Prompt 時，統一**強制 LLM 輸出 [0, 1] 之間的相對座標**。

### Step 2: 多模態 LLM 解析 (One-Shot API Call)
將原圖（搭配 System Prompt 與 RAG 術語表）一次性發送給 LLM。LLM 會在一份 JSON 文件內同時完成：
1. **字框偵測**：給出每個對話框的相對中心點與寬高 `[x, y, w, h]` (值域 0.0 ~ 1.0)。
2. **文字辨識 (OCR) 與翻譯**：精準讀取日文，結合前後文與腳色性格，翻譯成流暢的繁體中文。
3. **排版決策 (Typography)**：針對給定的方框寬高比，建議直排或橫排，並結合主角情緒（大吼、碎念）給出字體大小建議。

### Step 3: 重建與嵌字 (Inpainting & Rendering)
後端引擎拿到這份 JSON 後：
1. **反算絕對座標**：將 `[x, y, w, h]` 乘上原圖的 `width` 和 `height`，得出絕對像素。
2. **背景擦除**：使用輕量模型 (如 LaMa) 將這些絕對像素區域內的日文字抹除。
3. **渲染上字**：直接套用 JSON 內的 `render_config` (方向、對齊、行距、顏色)，呼叫渲染引擎（或交由 Web Canvas）在擦除過的背景上畫出帶有白邊的繁體中文。

## 2. 給 LLM 的系統指令 (System Prompt)

系統提示詞範例：

```text
你是一個頂級的漫畫在地化翻譯專家與排版設計師。
我將給你一張漫畫的頁面圖片，請你找出畫面上「所有」包含文字的對話框或旁白。

你的任務是回傳一份嚴格的 JSON 檔案，包含圖片中所有的對話。對於每一個對話框，你必須提供以下資訊：

1. `box_id`: 唯一的 ID，例如 "box_01"。
2. `original_text`: 從圖片上辨識出的原文（精確的 OCR）。
3. `translated_text`: 結合上下文與角色情緒，將原文翻譯為流暢生動的繁體中文。
4. `position`: 該對話框在圖片上的精確位置。
   ⚠️ 【極度重要座標規則】：
   你必須給出相對座標 `[x, y, w, h]`，其所有數值必須介於 0.0 到 1.0 之間。請提供**3到4位小數點的精確度**（例如 0.825 或 0.1234）。
   - `x`: 對話框中心的 X 座標比例 (從圖片左側算起)。
   - `y`: 對話框中心的 Y 座標比例 (從圖片上方算起)。
   - `w`: 對話框最大寬度的比例。
   - `h`: 對話框最大高度的比例。
5. `render_config`: 根據你的翻譯與對話框形狀，為台灣繁體中文設計的排版建議。
   - `alignment`: "left" (靠左/旁白), "center" (置中/常用), "right" (靠右)。
   - `direction`: "horizontal" (繁中預設橫排), "vertical" (僅限極度窄高的氣泡框使用)。
   - `font_size_offset`: 整數 (預設 0)。若畫面呈現大吼請給正整數 (+2 ~ +5)；若為小聲碎念給負數 (-1 ~ -3)。
   - `line_spacing`: 浮點數，行距，預設 0.2。
   - `fg_color`: [R, G, B]，多為黑字 [0, 0, 0]。若為深色底圖請改為白字 [255, 255, 255]。
   - `bg_color`: [R, G, B]，字體外層的描邊顏色。通常與字體顏色相反，確保文字清晰（例如黑字配白邊 [255, 255, 255]）。

確保整份輸出為有效的 JSON 格式。
```

## 3. 預期回傳的 JSON 結構 (LLM Output Schema)

輸出範例：

```json
{
  "dialogues": [
    {
      "box_id": "box_01",
      "original_text": "ふん…雑種が、思い上がるなよ！",
      "translated_text": "哼…雜碎，可別太得意忘形了啊！",
      "position": {
         "x": 0.820,  // 對話框中心位於整張圖 82% 的右側
         "y": 0.150,  // 對話框中心位於整張圖 15% 的上方
         "w": 0.120,  // 氣泡框寬度佔整圖的 12%
         "h": 0.350   // 氣泡框高度佔整圖的 35% (明顯是窄長形狀)
      },
      "render_config": {
        "alignment": "center",
        "direction": "vertical",        // LLM 判斷 h 遠大於 w，聰明地採用繁中也適用的直排
        "font_size_offset": 3,          // 高傲大吼的語氣，字體稍微放大
        "line_spacing": 0.2,
        "fg_color": [0, 0, 0],
        "bg_color": [255, 255, 255]
      }
    },
    {
      "box_id": "box_02",
      "original_text": "あの時……言えなかった言葉を。",
      "translated_text": "那時候……沒能說出口的話。",
      "position": {
         "x": 0.250, 
         "y": 0.750, 
         "w": 0.400, 
         "h": 0.100   // 寬扁型的內心獨白框
      },
      "render_config": {
        "alignment": "left",
        "direction": "horizontal",      // 適應寬扁形狀，採用標準橫排
        "font_size_offset": -1,         // 內心獨白，字體微縮
        "line_spacing": 0.3,
        "fg_color": [40, 40, 40],
        "bg_color": [255, 255, 255]
      }
    }
  ],
  "global_suggestions": {
    "recommended_font": "sans-serif",
    "notes": "第一句為強勢語氣，建議套用較粗的黑體或 POP 體。第二句為沉重回憶，建議採用明體。"
  }
}
```

## 4. `[0, 1]` 相對座標設計原則
*   **縮放不變性**：適應傳輸前的圖片壓縮，反算時乘上原圖尺寸即可還原絕對座標。
*   **精度考量**：需限制 LLM 輸出 **3 到 4 位小數**（如 `0.123` 或 `0.1234`），確保在高解析度原圖（如 4000px）下，像素誤差維持在可接受的次像素層級。
*   **模型適配**：相容多數 Vision 模型在物件偵測訓練時的 YOLO 標註格式。
